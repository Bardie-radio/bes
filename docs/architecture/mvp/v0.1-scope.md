# Bes MVP v0.1 scope

Ship Bes beside Kithara + Magpie + Plume so password login works end-to-end.

## In scope

- Container `bes`; join secret; Register + JWKS
- `GetProviders` (`form_schema`), `Authenticate`, `Refresh`
- Mint access + refresh JWTs; TTL config on Bes
- Ask Kithara to store user/binding (password hash in payload) on success
- Health; OTLP `bardie.auth.bes`; W3C trace context on RPCs

## Out of scope

- Public login UI (Bes never hosts login HTML)
- Optional HTTP façade for non-Bardie hosts ([03-optional-http](../03-optional-http.md) — **future planned**; leave Command + façade seams in MVP)
- Separate Bes user database
- OIDC / passkeys
- Account-linking UI (model in Kithara; multi-provider later)
- First-admin *policy* as Kithara env — operator user management (see Kithara auth-adapters)

## Implementation checklist

- [x] gRPC AuthAdapter + Register/Health against Kithara
- [x] Work verbs as **commands** / handlers; gRPC as façade only (seam for later HTTP)
- [x] Host persistence / ensure-user via Authenticate/`ensure_user` (Kithara owns DB)
- [x] form_schema provider descriptor
- [x] Authenticate (verify + mint JWT + ensure_user/binding)
- [x] Refresh path
- [x] JWKS publish for Kithara verify
- [x] TTL / signing key config
- [x] OTLP
- [x] Compose + join secret (`local/compose.phase2.yml`)
- [x] E2E: discovery → authenticate → Bearer call to Kithara `/api/auth/me`
