# Bes MVP v0.1 scope

Ship Bes beside Kithara + Magpie + Plume so password login works end-to-end.

## In scope

- Container `bes`; join secret; Register + JWKS
- `GetProviders` (`form_schema`), `Authenticate`, `Refresh`
- Mint access + refresh JWTs; TTL config on Bes
- Ask Kithara to store user/binding (password hash in payload) on success
- Health; OTLP `bardie.auth.bes`; W3C trace context on RPCs

## Out of scope

- Public login UI
- Separate Bes user database
- OIDC / passkeys
- Account-linking UI (model in Kithara; multi-provider later)
- First-admin *policy* as Kithara env — operator user management (see Kithara auth-adapters)

## Implementation checklist

- [ ] gRPC AuthAdapter + Register/Health against Kithara
- [ ] form_schema provider descriptor
- [ ] Authenticate (verify + mint JWT + ensure_user/binding)
- [ ] Refresh path
- [ ] JWKS publish for Kithara verify
- [ ] TTL / signing key config
- [ ] OTLP
- [ ] Compose + join secret
- [ ] E2E: discovery → authenticate → Bearer call to Kithara `/api`
